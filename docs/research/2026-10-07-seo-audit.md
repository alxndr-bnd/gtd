## New findings

### Critical

None.

### High

**H1. New pages are not in Google yet.**
- Evidence: URL Inspection 2026-10-07: `/bot` and `/en/todoist-alternative-open-source` are "URL is unknown to Google". `/` last crawl 2026-09-26, before all changes. The sitemap with 16 URLs was downloaded 2026-10-07.
- Why it matters: all on-site work since the baseline is invisible to search until Google crawls it. The SERBITO-434 8-week check depends on it.
- Fix: in the Search Console UI, run "Request indexing" for `/`, `/en/`, and the 8 new pages (the API cannot do it). Re-submit the sitemap. Optional: IndexNow for Bing/Yandex.
- Done when: URL Inspection shows "Submitted and indexed" (or at least crawled) for all 16 sitemap URLs.

### Medium

- **M1. Organization `url` is the LinkedIn page and there is no `logo`.** Set `url` to `https://serbito.rs/` (or gtd home), add `logo` ImageObject with `/icon-512.png`.
- **M2. `#app` node differs between RU and EN.** Same `@id` and `url`, but RU and EN pages emit a different `description` and `image`. Keep one description and image in the node; put language text in WebPage.
- **M3. One comparison table in three places.** Landing, `/alternativa-todoist` and `/en/free-gtd-apps` repeat the Todoist/TickTick/Things rows and "who should not switch" almost word for word. Cannibalization risk. Keep a short summary on the landing that links out; give each page its own query angle.
- **M4. Competitor facts will go stale.** Prices (Nirvana, TickTick) and "Telegram bot: not found" are dated "October 2026" for the whole table. Add a "checked" date per row and re-check every quarter.
- **M5. Screenshots are 600×1077 but show at ~184 px.** PSI: ~54 KiB waste on mobile. Serve ~370 px variants with `srcset`.
- **M6. Few images outside the landing.** The 3 screenshots are the only content images. Guides (`/bot`, `/weekly-review`) have none. Add the matching app screenshot to each guide.

### Low

- **L1.** `/en/free-gtd-apps` has no RU twin; `/gtd-dlya-nachinayushih` has no EN twin. By design now; add twins when there is time.
- **L2.** Guides use plain WebPage. Use `TechArticle`/`Article` with `headline`, `datePublished`, `dateModified`, `author` for `/weekly-review`, `/gtd-dlya-nachinayushih`, `/en/free-gtd-apps`.
- **L3.** Home pages have no `dateModified` and no sitemap `lastmod`.
- **L4.** WebApplication has no `screenshot`; `/shots/` files exist.
- **L5.** RU landing title is 68 chars (truncates); `/en/privacy` title is 27 chars.
- **L6.** `/changes` meta description is 97–105 chars (short).
- **L7.** RU /about has a ~270-word block; split it into 40–160-word passages for AI answers.
- **L8.** `/en/about` mobile LCP is 2.5 s in PSI (baseline 1.0 s local). Still Good; find the LCP element.
- **L9.** CLS 0.029 on `/` from `#signin` content. Good; reserve `min-height` to reach 0.
- **L10.** robots.txt repeats `Allow:` lines that `Allow: /` already covers. Cosmetic.
- **L11.** Inline body links on mobile are 18 px high (for example "Weekly Review", "What's new"); the email input is 43 px. Header "Open GTD" on guides is 21 px. Add vertical padding to reach 44 px.
- **L12.** Guides reuse the generic OG image. Optional: one OG image per guide.

**Not recommended:** FAQPage and HowTo JSON-LD. Google retired FAQ rich results and deprecated HowTo. The landing FAQ stays as plain HTML. The GEO agent suggested FAQPage for AI answers; the benefit is unproven, so it stays optional.

**Owner decision, not a finding:** Cloudflare returns 403 to AI *training* crawlers (ClaudeBot, GPTBot). AI *search* and user bots get 200.
